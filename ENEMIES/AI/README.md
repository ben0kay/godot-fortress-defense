# ENEMIES/AI — ST1 objective and breach targeting

**Status: Source Implemented / Awaiting Owner Validation.** `EnemyTargeting.cs` contains shared target validity, center-to-footprint attack range/solid line checks and direct cardinal cell-to-building boundary queries. `Enemy` caches the Citadel at spawn; `ActiveTarget` is either that Citadel or a temporary accessible breach building. No weighted targeting or scene-tree searches. Revised PL0 adds optional mobile-target choice as described below.

Reachability/selection runs inside the cooperative request queue described in `../MOVEMENT/README.md`, never in ordinary movement/attack ticks. Every chosen attack position is walkable, reachable from the job origin and outside the target footprint. Another wall/terrain blocks the contact line. After an opening, breachers reconsider the CPU. If no reachable damageable building exists, stop until topology changes instead of requesting endlessly.

## Revised PL0 — optional mobile objective

ICombatTarget (COMBAT) supplies typed damage, target bounds and one-shot loss notifications for Building/Player. The original StrategicTarget remains the cached CPU; NavigationTarget is the chosen CPU/mobile objective, while ActiveTarget can still be a temporary breach building. EnemyTargeting.ChooseObjective owns the simple Inspector rule: CitadelOnly, PreferNearbyPlayer (default), or NearestWithinRange, with PlayerDetectionRange500px. Stats snapshot at spawn.

EnemyTargetRoster caches one explicitly injected mobile target; it never searches scenes. A linked round-robin list processes at most4 cheap decisions/frame, normally at least.6s apart per enemy; higher populations can lengthen this interval. No player means no roster processing. Removal/death invalidates cached goals and queues CPU routes immediately; path work remains staggered by the existing shared queue.

Moving-player goals refresh at the decision cadence when the cell changes or the previous path ends outside attack range. Waiting enemies keep their queued job instead of cancelling every moving-target tick. Failed mobile reachability falls back to the CPU and caches the rejected cell/topology revision; it does not endlessly request the same unreachable player. Changed player cell/topology permits reconsideration. Player pursuit itself does not select walls; after fallback, normal CPU breach selection remains unchanged. Player/enemy body separation, predictive intercept, threat weights and optimal pursuit remain excluded. No-player selection/movement/attack semantics and queue limits are unchanged.

## EN2 — building hunting

BuildingHunterTargeting supplies nearest **footprint** distance, exact local filtering and global acquisition helpers. BuildingHunter policy never considers MobileTarget. EnemyTargetRoster.Initialize injects BuildingRegistry/projectile container; defaults are4 total decisions and1 global search/frame. Priority initial/recovery jobs coalesce; after two consecutive priority decisions, a due routine decision wins. Initial jobs are global; recovery first searches locally and schedules a separate global fallback only when needed. No buildings means sleeping off the routine list until registry addition. Normal local scans keep distant locked targets on empty results and only switch for15% improvement after1s. Per-instance phase spreads0.75–1.5s scans; actual latency can grow under load. Global/local counters are exposed to expanded F2 debug UI. See the Enemy002 README for lifecycle and owner checks.
